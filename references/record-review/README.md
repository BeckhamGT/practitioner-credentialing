# Pinned record-review rules

rules.json is an explicit engineering transcription of the confirmed office source tables and parameters. It is not a new office rule, a case answer, or a credentialing disposition. The adjacent text files are the previously retrieved native-document text extractions, preserved with hashes and semantic versions, not raw provider-original document exports. No caseload or later-batch evidence is included here.

Source-class classification recognizes exact exported delivery labels and the listed designated-source names, and checks the declared organization/board context. Unrecognized labels and secondary/impossibility routes remain for human source review. A listed source class does not prove a credential or its continued applicability after a revision. Unknown names, missing links and missing dates do not pass silently.

The roster transcription includes only the bodies and signatories needed for the two independent decision-authority checks. A valid body/role does not establish a matching applicant/revision, prior packet, admissible reason or valid supersession; these remain not evaluated. Clinical Director judgments are never generated by this reviewer.

Peer checks report individual returned fields only. They neither count qualifying references nor declare a reference element resolved. Signature currency is calculated at the export date only and is not a conclusion about an actual presentation. A February-29 anniversary without a governing calendar convention remains unknown, not silently shifted. Existing scoped source conflicts remain in docs/readiness-audit.md; the runtime does not read that combined source/case audit.

The caller supplies an explicit SHA-256 for rules.json. All referenced policy text hashes are checked, and a policy effective after the selected export date is rejected. Hash pinning prevents unnoticed changes relative to the selected rules; it does not authenticate an office rule or authorize a publication.
